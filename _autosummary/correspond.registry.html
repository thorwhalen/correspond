correspond.registry#

Which channels exist: the built-in channel table, the registry built from it, and what each channel needs.

The table (CHANNELS) is the one place a channel is described: its adapter’s factory, the optional modules and extra it needs, the binaries and platforms, and every setting with its environment variable and where to get it. Adapters read settings through value() and require(), so a variable name is written once.

The process registry (channels()) is an xdol.Registry built from the table on first use: a channel registers only when its optional modules import, and its adapter is constructed only when first asked for. check_requirements() explains what a channel is missing, without printing a secret.

>>> info("telegram").setting("token").env
'TELEGRAM_BOT_TOKEN'
>>> info("discord").planned
'https://github.com/thorwhalen/correspond/issues/2'
